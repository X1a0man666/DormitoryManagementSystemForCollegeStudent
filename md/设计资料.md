## 一、资料调研

### 1.1 南昌航空大学学院信息

依据：南昌航空大学教务处《2025年学院和本科专业设置一览》。
来源：[教务处页面](http://jwc.nchu.edu.cn/jxyj/zyjs/content_180682#1) · [第三方学院汇总](https://m.dxsbb.com/news/129298.html)

**17 个专业学院**（本项目采用，官方代码与学号规则一致）：01 材料科学与工程学院 / 02 环境与化学工程学院 / 03 机电学院 / 04 信息工程学院 / 05 航空宇航学院 / 06 动力与能源学院 / 07 数学与信息科学学院 / 08 仪器科学与光电工程学院 / 09 经济管理学院 / 10 体育学院 / 11 民航与交通学院 / 12 艺术设计学院 / 13 马克思主义学院 / 14 文法学院 / 15 航空服务与音乐学院 / 16 外国语学院 / 20 软件学院。

> 注：迭代二将初版占位学院列表（01-17，含"航空制造与机械工程学院""飞行器工程学院""通航学院(民航学院)"等旧名）替换为上述与 8 位学号规则一致的官方代码列表（01-16 + 20）。本项目数据存于 `data/colleges.txt`，可随时修改；与 `StudentId.VALID_COLLEGE_CODES` 保持一致。

### 1.2 南昌航空大学宿舍楼信息

来源：[阳光高考-投档及宿舍问题](https://gaokao.chsi.com.cn/zxdy/view--qid-5629513230,methodType-1.dhtml) · [2023招生问与答](https://tt.jxnews.com.cn/news/2214178#1#1) · [新生宿舍条件](https://www.yunhanyuan.com/ask/789.html)

- **32 栋标准学生公寓**：本科生 27 栋、研究生 4 栋、留学生 1 栋；另一来源称 28 栋（1-28 栋）——口径不一，本项目取 32 栋并做成**可配置数据**。
- **1-6 栋无独立卫浴**（公共卫生间/浴室），**7-28 栋有独立卫浴**；**25 栋为上床下桌**；楼栋最高 7 层。
- 4 人间为主；空调、热水、洗衣房、门禁等设施齐全。
- 有"天清苑"等"天"字开头命名风格。
- 学校按新生专业所在**学院统一分配宿舍**；但**楼栋→学院的具体分配规则不公开**。

### 1.3 结论与落地

- 学院、楼栋的**客观属性**（名称、卫浴、层数）采用真实信息。
- **楼栋→学院分配**不公开 → 做成 `data/buildings.txt` / `data/colleges.txt` 可配置数据，宿管科后续可在系统中调整（符合"查不到就保留接口"的约定）。
- 房间粒度（床位）为系统自身建模，无公开资料约束。

## 二、需求分析

- **角色**：宿管科、宿舍管理人员、辅导员、学生（四类账号登录）。
- **宿管科**：楼栋分配、宿舍管理人员管理、修理、售电。
- **宿舍管理人员**：夜归、卫生、贵重物品出入登记。
- **辅导员**：本学院宿舍分配与审批。
- **学生**：宿舍申请、转移、退出、购电、维修申请。
- **技术要求**：封装/继承/多态；JavaFX（禁 Swing/AWT）；文件存储；过程记录进报告。
- **已确认假设**：完整账号登录系统；学生申请先由辅导员审批，宿管科复核留后续；单机版；界面全中文。

## 三、设计过程

### 3.1 类设计（体现面向对象三要素）

```
                        RoleCapable（接口）
                              │
                    Person（抽象类：id/name/gender/phone/collegeCode
                           + 抽象方法 getRoleName/getRoleKey/getDutyDescription）
                    ┌──────────┴─────────────┐
              Student                     Staff（抽象：jobTitle）
                                    ┌─────────┼──────────┐
                               Counselor  DormStaff     Admin

宿舍信息（组合）：College ─→ Building ─→ Room ─→ Bed
日常记录：NightReturnRecord / HygieneRecord / ValuablesRecord
业务申请：DormApplication / RepairTicket / ElectricityPurchase
账号：Account（username/password/personId/roleKey）
```

- **封装**：所有字段 private + getter/setter；业务规则收敛在 service 层，界面不直接改数据。
- **继承**：`Person → Student`；`Person → Staff → Counselor/DormStaff/Admin`。
- **多态**：抽象方法由子类实现；`AuthService.login` 返回 `Person` 基类，调用方拿基类引用即可获得子类行为；`Storage` 接口 + `TextStorage` 实现可替换。

### 3.2 存储设计

- `Storage`（接口）：`load/save/hasFile`。
- `TextStorage`（实现）：`data/` 目录、每实体一文件、一行一记录、`|` 分隔、`#` 注释头、UTF-8。
- `DataCenter`（单例门面）：持有全部列表、加载/保存、查询、编号生成（AP/RP/EL/NR/HG/VA + 4 位序号）。
- 自由文本经 `TextUtil.escape()` 转义，防止破坏文件结构。

### 3.3 业务闭环设计（迭代一）

```
学生登录 ──提交入住申请──> 数据落库(PENDING)
    辅导员登录 ──查看本院待审批──> 选择目标楼栋内空床房间
        └──通过并分配──> 更新床位占用 + 学生当前宿舍 + 申请状态(APPROVED)
        └──驳回──> 申请状态(REJECTED)
```

校验规则：已入住不可重复申请；目标楼栋须在本学院分配范围内；房间须有空床；辅导员只能审批本学院学生。

### 3.4 学号规则设计（迭代二）

南昌航空大学本科生学号为 **8 位数字**，`StudentId` 值对象统一负责校验/解析/生成：

| 位 | 含义 | 取值范围/规则 |
|----|------|--------------|
| 1-2 | 入学年份后两位 | 2024 入学→24，2025 入学→25 |
| 3-4 | 学院代码 | 官方 01-16、20 |
| 5 | 专业代码 | 0-9（默认每学院 10 个专业） |
| 6 | 班级代码 | 1-9（默认每专业 9 个班） |
| 7-8 | 学号序号 | 01-99（默认每班 99 人） |

**关键规则：转专业后学号不变**。学号编码的是**入学时**的学院/专业/班级；学生当前学院/专业（`Person.collegeCode` / `Student.major`）可因转专业与学号不一致。示例：`24112322` = 2024 年考入民航与交通学院(11) 工程管理专业，3 班，学号 22 号（后转入软件学院，学号不变）。

## 四、设计结果（迭代一 / 迭代二）

- 完整源码位于 `src/com/nchu/dorm/`，共 32 个 Java 文件（含迭代二新增 `StudentId.java`）。

- 四角色界面框架全部就绪；学生申请→辅导员审批闭环可用。

### 迭代一过程中的关键问题

1. **静态字段初始化顺序 bug**：`DataCenter` 单例在 `DATA_DIR` 初始化前被创建 → 存储目录为 null → NPE。修复：调整声明顺序。详见 X1a0man01.md 第三节。
2. **测试数据污染**：冒烟测试改写数据文件，运行后清理 `data/` 恢复种子数据。
3. **编码**：统一 UTF-8（编译 `-encoding UTF-8`、文件读写 `StandardCharsets.UTF_8`），避免 Windows 中文乱码。
